## Важное

**В1. `crates/recorder/src/rawline.rs:68`: быстрый путь `seq_first == seq_last` обходит `envelope_seqs`. На диске и в живом разборе результат может разойтись.**
- Что: если в строке `seq_first == seq_last`, `seqs()` возвращает `seq_max = seq_first` и пустые дыры, а JSON не разбирает. Живой путь (`route::envelope_seqs`) считает максимум и дыры по всем сообщениям. Для конверта `[7, 9, 7]` живой путь даёт `seq_max = 9` и дыру `8..8`, диск даёт `seq_max = 7` и ни одной дыры. Для `[7, 3, 7]` живой путь даёт дыру `4..6`, диск — нет.
- Почему важно здесь: п. 1 задачи требует одного места, где выводятся seq_max и дыры. Этим местом стала `envelope_seqs`, но у `seqs()` осталось своё правило. `recover` берёт отсюда `resume_seq` (`file_seq_max`) и дыры (`scan_seq_holes`). Если такой конверт попадётся, recovery посчитает `last_seq` меньше, чем было, и не дозапишет дыру, которую записал бы живой writer. Тест `disk_reader_agrees_with_live_routing` этого не ловит: в наборе `[5,5]` разбор с диска и живой разбор совпадают случайно. На реальном фиде такие конверты маловероятны. Правило существовало и до 025, поэтому замечание не блокирующее.
- Исправление (меняет поведение только на таких патологических строках, формат сырья не меняет): убрать быстрый путь. Разбор JSON нужен только при старте, а recovery сканирует не больше трёх часовых файлов (`recovery.rs:233–262`), это порядка десятков тысяч строк.
  ```rust
  pub fn seqs(&self) -> Option<LineSeqs> {
      if self.seq_first == 0 && self.seq_last == 0 {
          return None;
      }
      let parsed = serde_json::from_slice::<FeedEnvelope>(self.json).ok();
      Some(match parsed.as_ref().and_then(envelope_seqs) { /* as now */ })
  }
  ```
  В `cases` теста добавить `&[7, 9, 7]` и `&[7, 3, 7]`. Если важна скорость старта (не измерял), оставить быстрый путь, но назвать его в doc `seqs()` явным допущением («конверт с `seq_first == seq_last` состоит из одного seq») и проверить это допущение на данных. Последнее — к data-auditor.

## Проверка пунктов задачи

1. **`envelope_seqs`.** Сделано, одна реализация. Оговорка — В1.
2. **Порядок в `FeedWriter::accept` (`writer.rs:171–215`).** `check` не меняет состояние (`seqtrack.rs`, `&self`). `Stale` возвращается до `ensure_hour`, поэтому файл часа не открывается. `ensure_hour` (`:191`) вызывается до постановки строк дыр в `pending_gaps`, `seq.advance` — после `write_line`. Коммит ротации публикует только прошлый час.
   - Тесты: `hour_rotation_publishes_gap_row_after_its_line` проверяет точное содержимое `gaps.tsv` и `last_seq` до и после commit, а также пустой файл нового часа. `gaps_and_last_seq_never_ahead_of_data_across_rotations` проверяет инвариант после каждого `accept`, сверяя с полными фреймами на диске через `valid_prefix_len`.
   - Мутационную проверку исполнителя не повторял.
   - Если `ensure_hour` падает, `pending_gaps` и счётчики больше не трогаются. Раньше они заполнялись до ошибки. Writer в этом случае всё равно останавливается, так что разница безвредна.
3. **Модуль `jitter`.** Только std. Функция вывода вынесена в `const fn mix` и `nth`, поток на процесс устроен как `OnceLock` (seed) + `AtomicU64` (позиция), без блокировок и без `unsafe`.
   - Тестируемость: детерминированная часть (`mix`, `nth`, `to_unit`) проверена по эталону. Недетерминированный `rand01` подменять не нужно: лестница принимает джиттер аргументом (`ladder.next_pause(..., jitter::rand01())`), и её тесты передают фиксированное значение.
   - Состояние общее на процесс, поэтому значения в тестах зависят от порядка вызовов. Ни один тест на конкретные значения `rand01` не опирается, так что хрупкости нет.
4. **`LineFault`.** `Copy`-enum с `&'static str` для имени столбца. `Display` побайтно повторяет прежние тексты, это проверяют `line_fault_texts_are_unchanged` и golden-тест `connlog`, где ожидаемая строка `gaps_line_skipped` не менялась. Прямого клиента `LineError::reason` вне recorder нет: enricher использует только `%e.reason` в `tracing` (`lib.rs:293`).
   - `# Errors` есть у всех публичных функций hood-core, которые возвращают `Result` (clippy `missing_errors_doc` = 0).
   - Doc `parse_quantity` теперь соответствует коду, добавлен тест на 20 цифр.
5. **Не-UTF-8 `gaps.tsv`.** Выбор (`from_utf8_lossy` + один WARN) согласован с уже принятой политикой 019 для битых строк и описан в doc `read_gap_ranges` и в `data-model.md`. Recorder `gaps.tsv` не переписывает, только дописывает (`append_synced`), поэтому плохие байты не размножаются и не теряются. Enricher (`--gaps`) по-прежнему отвергает такой файл целиком, и повреждение будет замечено. С точки зрения архитектуры решение приемлемое. Политику подтверждает Михаил (вопрос 1 отчёта).
6. **`Option<Slot>` вместо `Slot::Empty`.** Невозможное состояние стало явным `None`, оба `unreachable!()` ушли, поведение на ошибке прежнее.

Публичный API: в hood-core добавились `jitter::{SplitMix64, rand01}` (по `SplitMix64` см. Р1) и `ranges::LineFault`. Сигнатура `subtract` изменилась, оба вызова обновлены. В recorder `EnvSeqs` и `envelope_seqs` объявлены `pub`, но модуль `route` приватный (`lib.rs:59`), так что фактически видимость крейтовая, как у остального `route`.

## Что хорошо

- В `accept` порядок шагов объяснён в коде (почему `ensure_hour` идёт первым), и закреплён двумя тестами, один из которых проверяет инвариант после каждого шага, а не конкретный сценарий.
- `LineFault` сохранил тексты побайтно, и это закреплено отдельным тестом: формат `connections.tsv` и WARN-строк не сдвинулся.
- В `jitter` эталон `splitmix64.c` плюс тест совместимости со старым генератором recorder. Изменение поведения (поток вместо хеша от часов) описано честно.
- Newtype времени не стали делать попутно (отчёт, п. 5). Это правильно: широкий дифф без изменения поведения не должен попадать в один деплой с поведенческими правками.
