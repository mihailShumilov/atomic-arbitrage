## Замечания

- **З1. Потерю метаданных при `EXCHANGE TABLES` воспроизвёл независимо** (2026-10-02, тот же временный контейнер, `fakeowner`).
  - Сделал `CREATE xt.a`, `CREATE xt.b`, `EXCHANGE TABLES xt.a AND xt.b`. Команда без ошибки, но в каталоге метаданных остался только `b.sql`. После `docker restart` в базе одна таблица `b`.
  - Вывод исполнителя подтверждён, отказ от `EXCHANGE` в 003 и запрет в `data-model.md` обоснованы.
  - Предполагается, не проверено: `CREATE OR REPLACE TABLE` / `REPLACE TABLE` в Atomic-базе тоже используют атомарный обмен. Их стоит внести в тот же запрет.
- **З2. Остаток старой таблицы на основном томе.**
  - Каталог `data/clickhouse/store/fb1/fb1c8399-…/` (`format_version.txt`, пустой `detached/`) на 2026-10-02 всё ещё на месте.
  - Косметика, данных нет. Предположение отчёта «ClickHouse уберёт сам» пока не подтвердилось.
- **З3. Обрыв между двумя `RENAME`** чинится вручную (описано в 003). Повторный `apply.sh` в этом состоянии падает громко: первый `throwIf` обращается к несуществующей `funding_edges`, потерь нет. Приемлемо.
- **З4. Документация.** В `CLAUDE.md` («Команды») по-прежнему написано «схема из sql/ применяется при первом старте». Теперь нужно `docker compose up -d clickhouse && sql/apply.sh`. Исполнитель это отметил, файл вне его зоны. Решение за Михаилом/Cowork.
