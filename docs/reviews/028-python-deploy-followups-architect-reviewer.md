## Ответ на вопрос исполнителя: `write_state` при ошибке → журнал и `rc=1`

**Согласен.**
- `rc=1` в `healthcheck.sh` уже означает «проверка не смогла выполнить свою работу»: так же обрабатывается провал notify (стр. 93, 107, 122, 291, 405). Юнит с `OnFailure=notify-failure@%n.service` превращает это в уведомление. Ошибка записи состояния того же класса. Молчать о ней нельзя: при неписабельном `gaps.offset` каждый запуск повторял бы одну и ту же пачку дыр.
- Порядок «сначала notify, потом write_state» сохранён. При ошибке записи худший исход — повторное уведомление, а не потерянное. Для алертинга это правильная сторона.
- Атомарность корректна: временный файл `"$f.tmp.$$"` лежит в том же каталоге (rename в пределах одной ФС), `mv -f` заменяет файл. При ошибке временный файл удаляется, старый остаётся. Тест ловит неатомарную запись по смене inode, и перекрёстный прогон исполнителя со старым `healthcheck.sh` это подтверждает. `fsync` не делается. Для файлов состояния алертов это допустимо: после сбоя питания худший случай — повторное уведомление.
- Остаток `*.tmp.<pid>` возможен только при SIGKILL между `printf` и `mv`. Он безвреден: `healthcheck.sh` не перебирает каталог состояния по glob (проверено grep 2026-10-03), а файлы читаются по точным именам. Отдельная чистка не нужна.

## Структура и разбиение

Менять раскладку не нужно.
- `lib.sh` — минимальный набор из пяти функций, без абстракций на вырост. Варианты (`--noisy`, необязательный `t_diag`) покрывают все реальные различия бывших копий. Диагностика при FAIL сохранена там, где была (`t_diag` в mdadm, smartd, feed-audit-daily, healthcheck). У backup и notify её и раньше не было.
- `rpc_pick(blocks, sample, seed)` вынесена в чистую функцию на `random.Random(seed)`. Это правильная граница: детерминизм тестируется без zstd и без сети, а `check_rpc` остаётся тонким.
- `metrics(line, hour_start=None, obj=None)` — минимальное изменение, сигнатура обратно совместима (`hourly_summary.calibrate:147` вызывает `metrics(line)`). `line` по-прежнему нужен для `line_raw_b` и `line_zstd3_b`.

## Проверка дизайна `--seed`

- Вывод по умолчанию не меняется. Без `--seed` и при `--rpc-sample 0` остаётся `rpc {}`: это видно в коде (`feed_audit.py:795-799`) и закреплено тестом (`EndToEnd.test_rpc_seed`, текстовый и JSON-вывод). Исполнитель дополнительно сравнил 12 пар HEAD и рабочей копии побайтно, этот прогон я не повторял.
- Seed печатается, когда он нужен: всегда при выборке (по умолчанию `time.time_ns()`, его можно взять из отчёта для повтора), в том числе когда RPC упал (`rpc.seed` есть в возвращаемом словаре при любом `res`). Без выборки — только если задан явно. Это ровно формулировка задачи. Вариант `rpc {'seed': N}` без выборки немного избыточен, но безвреден и требуется задачей.
- Ежедневная обёртка (`feed-audit-daily.sh`) запускает аудит с `--rpc-sample 0` и без `--seed` (по тесту `test-feed-audit-daily.sh`), поэтому ежедневный отчёт на сервере не меняется.
- `min(blocks)` вместо повторной сортировки — корректная мелкая оптимизация с тем же смыслом (`seqs[0]` = минимум).
- py39: `time.time_ns` есть с 3.7, `random.Random(int).sample` детерминирован на 3.9 и 3.14 (тесты зелёные на обеих версиях по отчёту, на 3.9.6 проверено мной).
