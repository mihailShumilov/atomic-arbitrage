## Смена часа (проверено 2026-10-03, граница 22:00 UTC, `--frame-secs 30`)

Мок шлёт блок каждые 0,1 с, есть строки без seq. Дыры: +3 seq за 40 с до границы (внутри часа) и +7 seq ровно на границе: первая строка часа 22 идёт после дыры. Опрос каждые ~20 мс. Сначала читаются `last_seq.txt` и `gaps.tsv`, затем полные zstd-фреймы. Нарушения:
- `GAP` — строка `gaps.tsv`, у которой `recv_ns` нет среди строк в полных фреймах;
- `LS` — `last_seq` больше максимума seq на диске.

Пары HEAD и нового шли одновременно.

| Сценарий | HEAD | новый |
|---|---|---|
| **rotG**, непрерывная запись через границу (5 133/5 134 замера) | `GAP` = **1 099 замеров**: строка `50879 50885` в `gaps.tsv` с T+0,10 с, её строка данных на диске только с T+29,94 с; `LS` = 0 | `GAP` = 0, `LS` = 0. Строка `50879 50885` появилась на T+30,0 с, первый полный фрейм часа 22 — на T+29,92 с. Строка дыры внутри часа (`50483 50485`) появилась у обоих одновременно с данными |
| **rotGK**, kill -9 на T+1,5 с, рестарт | `GAP` = 921; после kill -9 в `gaps.tsv` осталась **строка-сирота** `60879 60885`: её строка данных так и не легла на диск, после рестарта сервер дослал эти seq, и в итоге строка `gaps.tsv` указывает на seq, которые в данных есть | 0 нарушений; сирот нет; `requested` = последняя строка часа 21 + 1 |
| **rotGB**, каталог дня только для чтения, файл часа 22 не открыть (writer error на ротации), рестарт | `GAP` = 920; сирота `70878 70884` (строка дыры для строки, которая вообще не была записана) | 0 нарушений, сирот нет, код 2, после рестарта дыр нет |

В конце у обеих версий дубли = 0, `holes_not_in_gaps` = 0, `last_seq` = максимум данных. В rotG сырьё и журнал совпадают побайтно. В rotGK/rotGB различие одно: в какой час попала граничная строка (у мока дыра сдвинулась на один seq из-за миллисекунд). Строка-сирота HEAD безвредна: enricher лишний раз скачает блоки. Но это ровно то нарушение правила data-model «строка дыры не раньше данных», которое задача и закрывала. Новое поведение совпадает с отчётом исполнителя (отличие «а»).

Мелочь (не замечание). В rotGB новый бинарник не пишет WARN `gap in feed` для дыры на строке, которую не удалось открыть: `ensure_hour` падает раньше, чем строка дыры встаёт в очередь. Дыра от этого не теряется: строка не записана, рестарт просит `last_seq + 1`, а если сервер начнёт позже, это поймают сверка восстановления и `first_minus_requested`.

## `gaps.tsv` не в UTF-8 (п. 4)

Во всех случаях HEAD выходит с кодом 1 (`Error: read …/gaps.tsv`): под systemd это crash-loop и потеря фида. Новый бинарник выходит с кодом 0, пишет ровно один WARN `gaps.tsv is not valid UTF-8 …` за старт, и `gaps.tsv` не переписывается: префикс побайтно прежний, только дописывание.

## Прочее (по чтению диффа, 2026-10-03)

- `writer::accept`: `ensure_hour` вызывается до постановки строк дыр и до `advance`; `Stale` возвращается раньше и файл часа не открывает. Для строк без seq `ensure_hour` вызывается, как и раньше в `write_line`. `Slot::Empty` → `Option<Slot>`: переходы те же, при сбое та же ошибка `writer in inconsistent state`.
- `envelope_seqs` — одна функция для `route_text` и `RawLine::seqs`. Запасной путь (битый JSON или пустые `messages` → больший из столбцов) прежний.
- `subtract(&[Range], &[Range])`: тело совпадает с HEAD, сменились только типы аргументов. Одна строка в enricher (`hr::subtract(&gaps, &filled.ranges)`) логику не меняет, `cargo check -p enricher` чисто.
- `LineFault::Display` даёт прежние тексты: строки `gaps_line_skipped broken` в журнале побайтно как у HEAD (c07, c08, c09, c15).
- `--help` нового бинарника побайтно как у HEAD.
