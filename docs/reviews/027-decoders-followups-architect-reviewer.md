## Проверка пунктов задачи

**1. Единая строгая hex-грамматика** (`src/model.rs:218` `hex_digits`). Проверено чтением кода и grep по крейту.
- Все четыре разборщика идут через `hex_digits`: `quantity_u256` (:227), `parse_addr` (:242), `parse_b256` (:249), `parse_bytes` (:256). `quantity_u64`/`quantity_u32` построены поверх `quantity_u256`.
- Других мест разбора hex в `crates/decoders/src` нет. Не осталось ни `parse::<Address>`, ни `strip_prefix("0x")`, ни прямого `hex::decode`, кроме самих хелперов. Реестр (`l1_inflows/registry.rs:147,150`) использует `parse_addr`.
- Каждая функция сама проверяет то, что относится только к ней: непустое значение для quantity, длину 40 или 64 для адреса и хэша, чётность для data (через `hex::decode`). Префикс и алфавит проверяет только `hex_digits`. Разделение верное.
- С `hood_core::hex::parse_quantity` грамматика quantity совпадает: обе отвергают `0X`, пустое значение и не-hex символы. Комментарий-сечение `model.rs:209-212` («keep in sync») остаётся верным.
- Тесты покрывают отказы: без префикса, `0X`, `0x0x`, длина ±1 байт, `_`, пустая строка; для data — `0x0x00`.

**2. З2 — `UnaccountedKind::UnregisteredGatewayEth`** (`l1_inflows/types.rs:146`, `l1_inflows/mod.rs:205`).
- Место выбрано правильно. Ветка стоит внутри `retry`, в той же точке, где решается судьба ETH шлюзовой `0x68`, и сделана как `else if` к `GatewayEthUnexplained`. Поэтому на одну tx получается не больше одной записи этих двух видов. Это гарантирует сама структура кода, отдельный тест не нужен.
- Имя ясное и следует схеме `<что>_<актив>`, как `gateway_eth_unexplained`. `as_str` = `unregistered_gateway_eth`.
- Вариант стоит последним. У enum derive `Ord`, поэтому порядок прежних видов в `BTreeMap` счётчиков сохраняется. Это согласуется с требованием задачи не менять вывод.
- Doc варианта и абзац в doc модуля (`mod.rs:30-32`) говорят «возможный приход» (может быть поддельный шлюз), то есть не обещают больше, чем есть. `data-model.md:100` совпадает с кодом.
- Тест на реальной фикстуре (блок 77312169, `--no-builtin`-эквивалент) плюс отрицательные проверки для `verified` и `observed`.
- Нового публичного API, кроме варианта enum, нет. Вне `decoders/src` `UnaccountedKind` используют только тесты, `match` по нему снаружи нет, поэтому новый вариант ничего не ломает.

## Рекомендации

**Р1. `clippy.toml` лучше держать в корне workspace** (`crates/decoders/clippy.toml`).
- Что не так: clippy ищет конфиг от каталога крейта вверх, поэтому файл в `crates/decoders` действует только на decoders. `ClickHouse` есть и в doc `crates/enricher/src/lib.rs`. Кто запустит рекомендательную команду pedantic из скилла (`--workspace`), увидит там то же предупреждение, а правило окажется разным для разных крейтов.
- Исправление: перенести файл в корень репозитория (`/clippy.toml`) с тем же содержимым. Поведение `-D warnings` не меняется. Можно сделать позже вместе с 025/028, когда параллельные правки закончатся.

**Р2. Повтор `!tx.value.is_zero()` в двух ветках** (`l1_inflows/mod.rs:203,205`).
- Сейчас условие о ненулевом value повторено в `if` и `else if`. Если кто-то поправит одну ветку и забудет другую, ветки разойдутся. Вложенная форма показывает «ETH есть — объясняем его» одним условием:
  ```rust
  if !tx.value.is_zero() {
      if token_sum != Some(tx.value) {
          out.unaccounted(b, UnaccountedKind::GatewayEthUnexplained, Some(to), tx.value);
      } else if registry.get(&to).is_none() {
          // Review 017, З2: ...
          out.unaccounted(b, UnaccountedKind::UnregisteredGatewayEth, Some(to), tx.value);
      }
  }
  ```
  Поведение то же. Мелочь.

**Р3. `parse_addr`/`parse_b256` — недостижимая ветка ошибки и повтор** (`model.rs:242-253`).
- После `hex_digits` и проверки длины `hex::decode` уже не может упасть, так что `map_err` в обеих функциях — мёртвый код. Сами функции отличаются только `N`.
- Если хочется одной строкой, подойдёт приватный generic:
  ```rust
  fn fixed_hex<const N: usize>(s: &str, what: &str) -> Result<FixedBytes<N>> {
      let h = hex_digits(s, what)?;
      ensure!(h.len() == 2 * N, "bad {what} {s:?}: expected {} hex digits", 2 * N);
      Ok(FixedBytes::from_slice(&hex::decode(h)?))
  }
  // parse_addr = fixed_hex::<20>(s, "address").map(Address::from); parse_b256 = fixed_hex::<32>(s, "hash")
  ```
  Две трёхстрочные функции тоже читаются нормально, так что можно оставить как есть. Тексты ошибок при переделке не должны меняться: на них опираются только `is_err()`, но формат хорош.

## Что хорошо (не сломать при правках)

- Одна точка правды для hex-грамматики, и doc объясняет, зачем ручная проверка: `const-hex` снимает второй `0x`, ruint пропускает `_`. Без этого комментария следующий читатель «упростит» обратно до `parse::<Address>()`.
- Новая запись З2 не меняет ни ребра, ни прежние виды, ни их порядок. Это добавочный сигнал с честной формулировкой «возможный приход».
- Деструктуризация без `..` в `into_swap`: любое новое поле `PoolSwap` заставит обновить код.
- Тест З2 построен на реальном блоке с хэшем tx в комментарии, а отсутствие записи проверено для обоих статусов реестра.
