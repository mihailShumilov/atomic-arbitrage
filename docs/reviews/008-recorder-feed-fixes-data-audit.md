## 1. З1 — сверка дыр при старте — PASS

## 3. Close 1000 при остановке — PASS

**Код, прочитан.**
- Сигнал взводит `watch`-флаг, main ждёт сетевой цикл не больше 5 с.
- `close_gracefully` делает следующее:
  - `Frame::close(Normal, "recorder shutdown")`;
  - до 2 с (`CLOSE_REPLY_WAIT`) читает кадры, все они пишутся в сырьё;
  - затем `ws.close()` не дольше 0.5 с.
- Только после этого закрывается канал к писателю.
- `next_frame()` в `select!` отменять безопасно: это `poll_fn(poll_next_frame)`, состояние лежит в `self`. Проверено по исходнику yawc 0.4.2.
- Было до 008: future сети ронялся в `select!` без Close. Это согласуется с отчётом исполнителя.

**Свой мок на Python.** Независимо от `mock_feed.rs`: сырой сокет на 127.0.0.1, мок сам разбирает маскированные кадры клиента.

| Сценарий | Что увидел мок | Выход |
|---|---|---|
| Мок отвечает на Close | Close с кодом 1000, причина `recorder shutdown`, через +0.001 с после SIGTERM. EOF TCP пришёл только после ответного Close. | 0 через 0.035 с; `client_close server_replied` |
| Мок молчит | Close 1000 через +0.000 с; EOF TCP через **+2.003 с** | 0 через 2.061 с; `client_close no_reply`, `waited 2002 ms` |

## 5. З4 — срок фрейма и потери при kill -9 — PASS

**Код, прочитан.**
- Срок фрейма — `frame_max − COMMIT_GUARD` (200 мс), считается от открытия фрейма, то есть от записи его первой строки.

## Замечания (не блокируют)

**Р1 (низкое): recover и feed-audit по-разному считают покрытие дыры.**
- `reconcile_gaps` при частичном покрытии дописывает только непокрытый остаток отдельной строкой.
- `feed_audit.py` требует, чтобы **одна** строка `gaps.tsv` покрывала всю дыру: `any(f <= g0 and g1 <= t)`.
- Проверено синтетикой: дыра 76532007..76568582, записанная двумя смежными строками (…76550000 и 76550001…), даёт FAIL «gap … is not listed in gaps.tsv».
- При обычной работе writer такое не возникает: он пишет каждую дыру одной строкой после fsync данных. Возможно только при ручной правке или частично совпадающих строках.
- Ошибка ложная, в безопасную сторону: FAIL, а не тихий PASS.
- Исправление: в feed-audit перед проверкой склеивать смежные и перекрывающиеся строки `gaps.tsv`.

**Р2 (низкое): TAB внутри валидного JSON остаётся в столбце JSON.**
- `write_line` удаляет из валидного JSON только `\n`/`\r`. Незначащий TAB между токенами остаётся, и в строке получается 5 TSV-полей.
- Воспроизведено своим моком: `{"version":1,\t"messages":…}` записан с TAB.
- recover (`splitn(4)`) и feed-audit (`split("\t", 3)`) это переживают, и feed-audit такое не ловит. Загрузчик, который делит строку по всем TAB, сломается.
- На реальных данных не встречалось: 0 из 11 983 строк 001–002. Фид шлёт компактный JSON (**предполагается**, что так будет всегда).
- Исправление: удалять и `\t` (в валидном JSON это тоже незначащий пробел) или записать в `data-model.md`: «делить строку не более 3 раз».

**Р3 (низкое): feed-audit на границе часа.**
- Фрейм прошлого часа recorder закрывает при первой строке нового часа. Если связи нет, то по сроку фрейма, то есть до ~60 с.
- Аудит, запущенный в этот промежуток сразу после HH:00, покажет «torn zstd tail in closed hour» на ещё открытом фрейме.
- Выведено из кода, не воспроизводилось.
- Для ежедневного аудита по cron: запускать через несколько минут после начала часа или задавать `--current-hour` явно.

Для сведения, вне объёма 008 (исполнитель сам поднял как вопрос 3): при idle-таймауте recorder по-прежнему рвёт соединение без Close.
