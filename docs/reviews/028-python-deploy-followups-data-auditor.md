### 2. `--seed`
- `--rpc-sample 0 --seed 42`: от дефолтного вывода отличается ровно одной строкой. В тексте `rpc {'seed': 42}`, в JSON `"rpc": {"seed": 42}`. rc=0.
- `--rpc-sample 20 --seed 42 --rpc-url http://127.0.0.1:9`, два прогона: выводы побайтно равны. `rpc {'seed': 42, 'sampled': 0, …}`, `FAIL rpc check failed: Connection refused`, rc=1. Отказ RPC попадает в FAIL, а не роняет аудит.
- `--rpc-sample 20` без `--seed`: seed печатается (`time_ns`), в двух прогонах он разный.
- `rpc_pick` напрямую и через `main` (`rpc_blocks` подменён заглушкой, которая записывает запрошенные блоки и бросает исключение; сеть не используется). Три записи, `--rpc-sample 50 --seed 7`:
  - блоки, которые `main` передаёт в `rpc_blocks`, равны `rpc_pick(blocks, 50, 7)`;
  - повтор с тем же seed даёт тот же набор, seed 8 даёт другой;
  - 50 уникальных seq, отсортированы, первый и последний блок записи входят, все seq есть в записи;
  - отложенных блоков (kind ≠ 3) 12 из 25, 13 из 20 и 12 из 35, это не меньше `sample // 4`;
  - выборка под 3.9.6 и под 3.14.7 совпадает (sha256 `repr(pick)`), то есть seed с сервера (3.14) воспроизводится на Mac (3.9);
  - крайние случаи: 1 блок → `[1]`, выборка больше записи → все блоки.
- Замена `sorted(blocks)[0]` на `min(blocks)` эквивалентна: на пустом `blocks` `check_rpc` не вызывается, потому что раньше срабатывает `no blocks found`.

## Замечания (не блокируют)

**З1. Повторное уведомление и вводящая в заблуждение строка журнала при ошибке `write_state`.** При ошибке записи `write_state` ставит `rc=1`, но вызывающий код всё равно пишет `gaps: notified N new rows` (и `alert sent: …` в `raise`). Offset не сдвинулся, поэтому следующий запуск уведомит ту же дыру ещё раз (проверено, см. п. 5). Это семантика «хотя бы один раз», и сбой виден через `rc=1` → `notify-failure@`. Принять можно, но лучше логировать «notified» только при успешной записи. Есть и узкий случай, где HEAD работал, а новая версия нет: каталог стал недоступен на запись посреди запуска, а файл доступен. На практике его закрывает проверка `cannot write state dir` в начале скрипта.

**З2. `hourly_summary.py`: пустая ячейка `*_wei` теперь превращается в `None`, а не в `NaN`.** `base_fee_wei / 1e9` на `None` упал бы с `TypeError`, раньше получился бы `NaN`. Сейчас это не достижимо: `hourly_metrics.py` всегда пишет `base_fee_wei` числом (`baseFeePerGas` или 0). Пустым бывает только `fee_median_wei` (2 строки из 1 392), а сводка его не использует. Риск появится только при новом использовании wei-колонок.
