   - **Идемпотентность.** `ReplacingMergeTree`, строки при повторе идентичны. `feed_recv_ns` сливается как минимум из значения в таблице и значения из фида, поэтому перезагрузка без фида его не стирает.

## Предполагается / не проверено

- **Масштаб.** Атомарность проверена на 2,5 млн строк одной вставки; самый большой файл здесь — 79 446 логов. Память: файл и его TSV целиком в памяти. Для 200–1 000 блоков это десятки МБ, на большом архиве не мерил.
- **`feed_recv_ns` для длинного фида.** Индекс ограничен диапазонами из имён `blocks-<from>-<to>`. Если загружать вместе с `hourly-*` (диапазона в имени нет), индексируется весь фид, и на сутках фида это сотни МБ.
- **Lightweight `DELETE` в откате** проверен на одном сценарии (4 блока, три таблицы). Как он ведёт себя при параллельных слияниях и на больших таблицах — не проверено. Правило `insert-mutation-avoid-delete` не нарушается: оно запрещает мутацию `ALTER TABLE … DELETE` и само рекомендует `DELETE FROM` (исправлено после ревью, Р10).
- **Открытый (текущий) час recorder.** Его файл заканчивается незакрытым фреймом, загрузчик отклонит его как битый zstd. Грузить нужно закрытые часы; на живом сервере не пробовал.
- **Конфликты с параллельными задачами.**
  - `cargo fmt -p decoders` в начале моей проверки мог переформатировать файлы 033 (`swap_rows.rs`, `pools.rs` и др.), которые тогда были в работе. Содержимое не менял.
  - В `model.rs` 033/031 правок, похоже, не вносили, но в diff это видно одной кучей.

## Правки после ревью (architect-reviewer, `docs/reviews/032-clickhouse-loader-architect-reviewer.md`, 2026-10-05)
