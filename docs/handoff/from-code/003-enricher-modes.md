По пунктам задачи:

1. **`blocks`**: как раньше, `eth_getBlockByNumber(full=true)` + `eth_getBlockReceipts` пакетами. Добавлена проверка каждого блока; при несовпадении — повтор, затем остановка, блок не пропускается:
   - поле `number` = запрошенному;
   - число чеков = числу транзакций;
   - `blockHash` каждого чека = `hash` блока;
   - `transactionHash[i]` = `transactions[i].hash`.

   При записи проверяется непрерывность номеров. Команда из `CLAUDE.md` (`--from/--to/--out-dir`) работает без изменений.
2. **`logs`** (`--mode logs`): `eth_getLogs` с `topics: [[t1..tN]]`, по умолчанию все `decoders::ALL_TOPIC0` (4 шт.), свой фильтр задаётся через `--topic0` (можно повторять).
   - Окно: начальное `--logs-window` 500, потолок `--logs-window-max` 5000. Ошибка «too many results / block range / response size» или таймаут — окно делится пополам; успех — удваивается. Если не проходит окно в 1 блок, прогон останавливается.
   - Выход: `data/logs/logs-<from>-<to>.jsonl.zst`. Первая строка — `{"meta":{"format":"hood-logs-v1","mode":"logs","not_full_blocks":true,"reverted_txs":"absent: …",…}}`, дальше по строке на каждый блок диапазона, включая пустые: `{"number":N,"logs":[…]}`.
   - С блоками спутать нельзя: другая папка, другой префикс, meta-строка, ключ `logs` вместо `block`/`receipts`. В `filled.tsv` не пишется.
3. **`--gaps <file>`** (можно повторять): читает `from \t to \t recv_ns`.
   - Дыры сливаются, из них вычитается `data/blocks/filled.tsv`, остаток режется на файлы по `--chunk` (по умолчанию 1000 блоков) и качается в режиме `blocks`.
   - `filled.tsv` (`from \t to \t file \t unix_s`) дописывается с fsync только после rename файла. Прогон по диапазону тоже пишет в `filled.tsv`, поэтому `--gaps` не перекачивает то, что уже скачано диапазоном.
   - Есть `--dry-run` (план без вызовов) и `--max-blocks` (отказ, если план больше). Отсутствующий файл дыр — ошибка.
4. **Атомарная запись**: `<final>.partial` → `finish` zstd → `fsync` → `rename` → `fsync` папки.
   - При ошибке или Ctrl-C/SIGTERM незавершённый файл удаляется в `Drop`, а `filled.tsv` не трогается.
   - После `kill -9` остаётся только `*.partial`; следующий запуск в этой папке его удаляет.
   - Удаление безопасно: папку держит эксклюзивный `flock` (`.enricher.lock`). ОС снимает его и при `kill -9`, так что вечных блокировок нет. Второй enricher в ту же папку отказывается стартовать.
5. **429 и ошибки**:
   - `Retry-After` в секундах соблюдается (потолок 600 с); без него — экспоненциальная пауза 500 мс·2^k с «equal jitter», потолок 60 с (`--backoff-ms`).
   - Повторяются: 429, другие не-2xx, транспортные ошибки, таймауты, неполный или битый пакет, JSON-RPC-ошибка лимита внутри HTTP 200, null-результат.
   - После `--max-attempts` (по умолчанию 8) — остановка с ошибкой вида `blocks 5..=9: giving up after 3 attempts, last error: http 429`.
   - **После инцидента добавлено:**
     - `--rps` теперь считает JSON-RPC **вызовы** в секунду, пакет из N вызовов занимает N слотов (раньше считались HTTP-запросы);
     - 429 ставит на паузу все параллельные задачи, а не одну;
     - `--max-calls` — жёсткий бюджет вызовов на прогон с учётом повторов. Прогон останавливается до отправки запроса, который вышел бы за бюджет.
6. **Счётчики**: в конце прогона (в том числе после Ctrl-C и ошибки) в лог выводятся:
   - HTTP-запросы и байты тел ответов;
   - число ответов 429 и прочих не-2xx;
   - транспортные ошибки, таймауты, JSON-RPC-ошибки лимита, повторы;
   - вызовы по методам;
   - по каждому методу: принятые результаты, байты сырого JSON и потока zstd-3, среднее на результат (для `eth_getBlockByNumber`/`eth_getBlockReceipts` это среднее на блок).

   `--stats-json <file>` пишет то же в JSON.
7. **Тесты** — ниже.

## Что не получилось

1. **Превышен лимит 4 000 вызовов: за задачу 8 641, из них 8 040 в первой части.** Я запустил 1 000 блоков с `--rps 2 --batch 10 --concurrency 2`. Тогда `--rps` ограничивал HTTP-запросы, то есть до 40 вызовов/с. Публичный RPC отвечал 429 на 82 % запросов, и каждый повтор заново отправлял пакет из 20 вызовов. Бюджета вызовов в коде не было. Вывод шёл через `tail`, поэтому я ~11 минут не видел повторов.
   - Исправлено: `--rps` в вызовах/с, общая пауза после 429, жёсткий `--max-calls`. Всё покрыто тестами.
   - Вживую подтверждено в доборе: при `--rps 2` 0 ответов 429 на 600 вызовов, `--max-calls` соблюдён.
   - Предполагается (не проверено): ответы 429 отдаёт Cloudflare или лимитер до ноды. В счёт лимита я включаю все вызовы.
2. **Предел диапазона `eth_getLogs` на публичном RPC не найден.** 100 блоков прошли одним вызовом. Как узел сообщает о «слишком большом» запросе, не видели; адаптивное окно при таком ответе проверено только на моке.
3. **`--gaps` проверен на срезе в 300 блоков, а не на всей дыре 76532007..76568582** (36 576 блоков, ~73 тыс. вызовов). Всю дыру закрывать на публичном RPC нельзя, это работа для провайдера.
