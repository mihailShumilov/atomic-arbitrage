## Известные недостатки из «Контекста»

| Недостаток | Итог | Как установлено |
|---|---|---|
| recorder: один zstd-фрейм на весь час, при kill -9 хвост нечитаем | **подтверждено** | Во время записи (~2-я минута) `zstd -lv` на открытом файле показывал 0 завершённых фреймов; распаковывалась только часть уже сброшенных данных. Фрейм закрывается только в `finish()`, при ротации или остановке. Сам kill -9 не проверял, чтобы не открывать лишнее соединение |
| нет обработки SIGTERM | **подтверждено по коду** | В `main` ловится только `tokio::signal::ctrl_c()`, то есть SIGINT. На SIGTERM, например от systemd, фрейм не закрывается, и срабатывает предыдущий пункт |
| пауза переподключения максимум 30 с | **подтверждено по коду** | `backoff * 2`, `.min(30 s)`. После успешного `Ok(())` сбрасывается до 250 мс, но `run_connection` никогда не возвращает `Ok`. Отдельной обработки 403/429 нет. В этом прогоне переподключений не было |
| конверты без `messages` и нетекстовые фреймы отбрасываются | **подтверждено по коду** | `if frame.opcode() != OpCode::Text { continue }`; `let Some(..) = env.seq_range() else { continue }`. Отброшенное нигде не считается и не логируется, поэтому сколько таких было за 10 минут, неизвестно |
| enricher: только режим диапазона | **подтверждено** | Есть только `--from/--to` |
| enricher: запись не атомарная | **подтверждено по коду** | `File::create` сразу по итоговому пути. При падении посреди прогона останется усечённый `.jsonl.zst` с «правильным» именем |
| enricher: 429 не обрабатывается | **частично** | HTTP 429 попадает в общий повтор: 6 попыток, пауза 0.5→16 с, `Retry-After` не учитывается. JSON-RPC ошибка внутри ответа с HTTP 200 (некоторые провайдеры так сообщают о лимите) сразу валит весь прогон через `bail!` без повтора |

## Замечено сверх списка (не чинил)

- **Бинарники не читают `.env`.** dotenv в зависимостях нет, поэтому переменные надо экспортировать в оболочку: `set -a; . ./.env; set +a`. Иначе `RPC_URL` из `.env` игнорируется и берётся значение по умолчанию. Сейчас это совпадает с публичным RPC, но с ключом провайдера это тихо сломается.
- **MCP clickhouse не видит пароль.** `.mcp.json` подставляет `${CLICKHOUSE_PASSWORD}` из окружения, в котором запущен Claude Code, а не из `.env`. Результат — `AUTHENTICATION_FAILED`, см. ниже.
- **Порты ClickHouse открыты на всех интерфейсах.** В `docker-compose.yml` указано `"8123:8123", "9000:9000"`, то есть 0.0.0.0. На Mac в общей сети или на сервере так нельзя. Нужно `127.0.0.1:8123:8123`. Пароль по умолчанию из примера (`change-me`) я заменил на случайный.
- **Образ `clickhouse/clickhouse-server:latest` не закреплён.** Сейчас запущен 26.9.6.6.
- **`cargo run -p recorder` пересобирает часть зависимостей** после `cargo build --workspace`: без `--workspace` набор features другой. Это безвредно, но первый запуск recorder займёт ~12 с.
