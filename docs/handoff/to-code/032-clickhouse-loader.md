## Зачем
Схема готова (миграции 001–004, `sql/apply.sh`), декодеры дают строки (`rows.rs`). Нужен загрузчик, чтобы аналитика работала на ClickHouse. Сначала — локально на Mac; ClickHouse на сервер — отдельное решение Михаила.

## Что сделать
1. Новый крейт или бинарник `loader` (решить и обосновать): загрузка в `hood.blocks`/`hood.txs`/`hood.logs` из `blocks-*.jsonl.zst`, в `hood.feed_gaps` из `gaps.tsv`, в `hood.funding_edges` из декодера L1 (`l1_inflows`), время прихода из фида (`feed_recv_ns`) по копии сырья.
2. Требования из ревью (обязательно): `zstd -t` (или проверка контрольной суммы) до загрузки файла, вставка файла целиком или откат; валидация полей перед вставкой (ClickHouse молча превращает пустое в `''`/0 — пустой `block_number` недопустим); `feed_gaps` — ключ только `from_seq`, повторы диапазонов убирать; не засчитывать одновременно `unregistered_gateway_eth` и `l1_token` со статусом `none`; явный список колонок (`TabSeparatedWithNames`/`JSONEachRow`), порядок из `COLUMNS`; идемпотентность (повторная загрузка того же файла не меняет итог после `FINAL`).
3. HTTP к локальному ClickHouse 127.0.0.1:18123 (пароль из `.env`, не печатать, не в argv); без новых тяжёлых зависимостей (reqwest уже есть).
4. Тесты: на временном ClickHouse (bind-монтирование, уникальный порт 127.0.0.1, удалить после) — загрузка `data/blocks` + `data/samples` + копии фида; повтор — те же числа; сверка числа строк с исходниками.
