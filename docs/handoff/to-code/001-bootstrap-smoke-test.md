status: ready

## Зачем
Репозиторий развёрнут из архива `atomic-arbitrage-bootstrap` (версия от 28.09, до исправлений прежней сессии). Прежде чем чинить и расширять, нужно убедиться, что стартовый набор собирается, работает против живой сети и что Claude Code видит агентов, скиллы и MCP.

## Контекст
- `CLAUDE.md`, скилл `hoodchain-mev` (особенно `references/chain-facts.md`, `data-model.md`), скилл `cowork-handoff`.
- Известные недостатки этой версии (чинить НЕ в этой задаче, только подтвердить или опровергнуть в отчёте): recorder держит один zstd-фрейм на весь час (при kill -9 хвост часа нечитаем), нет обработки SIGTERM, пауза переподключения максимум 30 с (на 403/429 этого мало), конверты без `messages` и нетекстовые фреймы отбрасываются; enricher — только режим диапазона, запись не атомарная, 429 не обрабатывается.

## Что сделать
1. `cargo build --release --workspace`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`. Зафиксировать версии rustc/cargo. Если clippy падает — исправить только тривиальное (без изменения поведения), остальное перечислить.
2. `cp .env.example .env`, если `.env` нет. `RPC_URL` — публичный `https://rpc.mainnet.chain.robinhood.com`, если Михаил не дал ключ провайдера.
3. Запустить recorder на 10 минут: `cargo run --release -p recorder -- --out-dir data/feed`. Остановить через Ctrl-C (SIGINT). Одно подключение, без экспериментов с переподключениями.
4. Проверить запись (data-auditor): число конвертов, первый/последний `sequenceNumber`, число блоков, есть ли дыры внутри (`gaps.tsv`), размер файла, МБ/ч, блоков/с (по `recv_unix_ns`). Файл читается `zstd -dc` целиком. Сколько раз сервер закрывал соединение и с каким кодом.
5. Взять 20 блоков из записанного диапазона и прогнать enricher: `cargo run --release -p enricher -- --from <N> --to <N+19> --out-dir data/blocks`. Сверить `blockHash` из фида с RPC для этих 20 блоков.
6. Проверить окружение Claude Code:
   - `/agents` — видны все 7: indexer-engineer, data-auditor, skeptic-analyst, arb-researcher, engine-engineer, infra-ops, contract-reviewer;
   - скиллы `hoodchain-mev` и `cowork-handoff` подхватываются (описание видно, файлы читаются);
   - `.mcp.json`: context7 отвечает (любой запрос по `alloy`); clickhouse — отметить, запущен ли `docker compose up -d clickhouse` и доступен ли MCP. Если Docker не установлен — не ставить, просто отметить.

## Что НЕ делать
- Не исправлять recorder/enricher по существу — это задачи 002 и 003.
- Не открывать больше одного соединения к фиду, не делать серий быстрых переподключений (риск 429 и бана IP ~1 ч).
- Не коммитить `data/` и `.env`.
- Не писать ничего, что подписывает или отправляет транзакции.

## Критерии приёмки
- Сборка и тесты проходят; clippy чист или список предупреждений в отчёте.
- 10 минут записи: ≥ 5 500 блоков (ожидаем ~6 000 при ~10 блоках/с), дыры перечислены с причинами.
- 20 блоков: `blockHash` фида = `blockHash` RPC во всех 20.
- `/agents` показывает 7 агентов; оба скилла доступны; статус context7 и clickhouse в отчёте.

## Стоимость и риски
- RPC: ~40 вызовов публичного RPC. Деньги: 0.
- Диск: ~15–20 МБ фида.
- Риск: единственный IP сейчас — Mac Михаила; одно подключение на 10 минут безопасно.
