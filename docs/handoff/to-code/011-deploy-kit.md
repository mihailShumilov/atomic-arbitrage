## Зачем
Михаил заказывает сервер (0003, вариант B: недорогой сервер в ЕС, Ubuntu 24.04). Чтобы запись началась в тот же день, всё для развёртывания и мониторинга должно быть готово и проверено заранее.

## Контекст
- `deploy/recorder.service`, `deploy/README.md` (008: `RestartSec=120`, пауза между подключениями, Close).
- `docs/decisions/0003-recorder-server.md` — обязательные пункты: выделенный IPv4, chrony, бэкап сырья вне сервера, мониторинг (дыра > 5 мин, диск > 80%, бан).
- Тесты фида — никогда с IP сервера.

## Что сделать
1. `deploy/bootstrap.sh` — идемпотентный, для чистой Ubuntu 24.04 под root: пользователь `hood`, каталоги `/opt/hoodchain-mev/{bin,deploy}`, `/srv/hood/data/{feed,blocks,logs}`; chrony (и проверка синхронизации); ufw (только ssh); лимиты journald; установка юнитов. Docker/ClickHouse — отдельный флаг, по умолчанию выключен.
2. Сборка: самый простой надёжный путь — собирать на сервере (`rustup` + `cargo build --release -p recorder -p enricher`) скриптом `deploy/build-on-server.sh`; либо обоснованный кросс-компайл с Mac. Без новых зависимостей в workspace.
3. `deploy/healthcheck.sh` + `healthcheck.timer` (каждые 5 мин): recorder `active`; возраст последней строки фида (по mtime `last_seq.txt` / текущего файла) < 5 мин; диск < 80%; в `connections.tsv` нет свежих `403`/`429`/`startup_wait`; новые строки в `gaps.tsv`. Уведомление — через подключаемый notifier: по умолчанию journald, опционально Telegram (`/etc/hoodchain/notify.env`: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, не в git). Не спамить: одно уведомление на событие + «восстановлено».
4. `feed-audit.timer` — раз в сутки в 00:10 UTC по прошлым суткам (`--rpc-sample 0` до появления провайдера), итог — в лог и `/srv/hood/reports/feed-audit-YYYYMMDD.txt`; FAIL → уведомление.
5. Бэкап: `deploy/backup.sh` (restic или rclone на S3-совместимое хранилище / Storage Box) с плейсхолдерами; закрытые часовые файлы — неизменяемые, инкрементально; не включён по умолчанию.
6. `deploy/README.md` — runbook «от пустого сервера до записи»: что Михаил даёт (IP, ssh-ключ, при желании Telegram-бот), команды по шагам, как проверить первые 15 мин записи, как обновить бинарник без дыры (SIGTERM → замена → старт; пауза 120 с ожидаема), чек-лист перед уходом.
7. Шаблон `enricher-gaps.service`/`.timer` для дозаливки дыр — **выключенный**, с обязательным `--max-calls`; включать после выбора провайдера (0002).

## Что НЕ делать
- Никаких покупок, регистраций, подключений к реальным серверам и к фиду; вызовов RPC 0.
- Не коммитить токены, IP, ключи.
- Не менять код recorder/enricher (если нужен флаг — вопрос в отчёт).

## Критерии приёмки
- `shellcheck` чистый по всем скриптам; `bash -n` ок.
- `bootstrap.sh` прогнан в контейнере `ubuntu:24.04` (docker на Mac, только 127.0.0.1, порты не публикуются) дважды подряд — второй прогон ничего не меняет; шаги, требующие systemd, — проверены `systemd-analyze verify` на юнитах (в контейнере с systemd или описать, как проверено).
- `healthcheck.sh` проверен на подставных данных: тихий фид, 403 в `connections.tsv`, новая дыра, заполненный диск (имитация порога) — по каждому случаю ровно одно уведомление.
- indexer-engineer подтвердил пути, флаги и поведение рестарта recorder.
