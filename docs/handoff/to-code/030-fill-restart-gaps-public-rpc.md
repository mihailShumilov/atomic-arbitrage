# 030 — Залить две дыры от плановых рестартов через публичный RPC

## Зачем
Критерий фазы 1a — 7 суток записи без незаполненных дыр (запись с 2026-10-01 09:57Z, срок ~2026-10-08 10:00Z). В серверном `gaps.tsv` две дыры от плановых рестартов: 78504700..78505336 (637 блоков) и 78780059..78780154 (96 блоков). Провайдер RPC не выбран (0002), `enricher-gaps.timer` выключен. Решение Михаила 2026-10-05: делать всё, что не требует провайдера; эти 733 блока — ~1 500 вызовов публичного RPC.

## Что сделать
1. Скопировать с `hood-rec` только `gaps.tsv` (только чтение на сервере).
2. На Mac: `enricher --gaps <копия> --out-dir <scratch>` против публичного `RPC_URL` из `.env`, `--rps 2`, `--max-calls` с запасом (≤ 2 000), свой User-Agent если есть флаг; файлы с контрольной суммой (026).
3. Проверка: `zstd -t`, непрерывность и `parentHash`, число tx = число чеков, `blockHash` на стыках дыр совпадает с соседними блоками фида (из серверного сырья — rsync только нужных закрытых часов, только чтение).
4. Подготовить для Михаила команды: rsync файлов `blocks-*.jsonl.zst` и `filled.tsv` в `/srv/hood/data/blocks/` и `chown hood:hood`; после этого healthcheck `backfill=ok` и аудит: дыры закрыты.

## Что НЕ делать
- Никаких подключений к фиду; RPC — только публичный, ≤ 2 000 вызовов; на сервере ничего не писать (это команды Михаилу); recorder не трогать.

## Критерии приёмки
- 733 блока скачаны, все проверки п. 3 зелёные; data-auditor: PASS (сверка `hash` 20 случайных блоков с RPC в пределах бюджета, стыки с фидом).

Сделано; вызовов; проверено и как; команды для Михаила. `status: done` после выкладки на сервер, отдельный коммит.
