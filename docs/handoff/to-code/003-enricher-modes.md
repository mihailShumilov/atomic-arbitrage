# 003 — enricher: режим logs, режим gaps, атомарная запись, обработка 429

## Зачем
Дозаливка дыр фида через RPC — обязательная часть системы (дыры — норма). Сейчас enricher умеет только диапазон, пишет файл не атомарно и падает на 429. Эти исправления уже делались в потерянной сессии, их нужно восстановить.

## Контекст
- `crates/enricher/src/main.rs` (TODO в шапке: `--gaps`, `--follow`, загрузка в ClickHouse).
- `references/chain-facts.md`: `eth_getBlockReceipts` работает, в чеке есть `status`, `gasUsed`, `gasUsedForL1`, `effectiveGasPrice`, `from`, `to`, `logs`.
- Откатившиеся транзакции видны только через блоки+чеки; в режиме `eth_getLogs` их нет — это нужно явно помечать в выходных файлах.

## Что сделать
1. **Режим `blocks`** (текущий): `eth_getBlockByNumber(full=true)` + `eth_getBlockReceipts`, как сейчас.
2. **Режим `logs`**: `eth_getLogs` по диапазону блоков с фильтром по списку topic0 (по умолчанию — все из `crates/decoders`), адаптивный размер окна (уменьшать при ошибке «too many results»/таймауте, увеличивать при успехе). Выход: `data/logs/logs-<from>-<to>.jsonl.zst`. В метаданных файла/имени — режим, чтобы потом нельзя было спутать с полными блоками.
3. **Режим `--gaps data/feed/gaps.tsv`**: дозалить все незаполненные дыры в режиме `blocks`; вести `data/blocks/filled.tsv` (какие диапазоны закрыты). Повторный запуск не качает закрытое.
4. **Атомарная запись**: писать в `*.partial`, `fsync`, затем `rename` в финальное имя. Частичный файл никогда не носит полного имени. При старте — удалить или докачать `*.partial`.
5. **429 и ошибки**: соблюдать `Retry-After`; экспоненциальная пауза с джиттером; ограничение запросов в секунду параметром `--rps`; после N неудачных попыток — остановиться с понятной ошибкой, а не пропустить блок молча.
6. **Счётчики**: в конце — число вызовов по методам, байт получено, среднее байт на блок для `eth_getBlockReceipts` и `eth_getBlockByNumber` (нужно для решения 0001).
7. Тесты: атомарная запись (прерывание → нет файла с финальным именем); повтор после 429 (мок-сервер); `--gaps` не качает закрытые диапазоны.

## Что НЕ делать
- Не менять формат `blocks-*.jsonl.zst`.
- Не гонять большие диапазоны на публичном RPC: максимум 2 000 блоков в сумме за задачу, `--rps` ≤ 5.
- Загрузку в ClickHouse и `--follow` пока не делать — отдельная задача после решения по провайдеру.

## Критерии приёмки
- `cargo test`, clippy чистые.
- Ручной тест: `--gaps` на дырах из 001/002 закрывает их; data-auditor сверяет `blockHash` и число транзакций на 100 случайных блоках с RPC → PASS.
- Прерывание (Ctrl-C) в середине диапазона не оставляет файла с финальным именем.
- В отчёте: средний размер ответа `eth_getBlockReceipts` и `eth_getBlockByNumber(full)` в байтах (сырой JSON и после zstd) на ≥ 1 000 блоков.

## Стоимость и риски
- ≤ 4 000 вызовов публичного RPC. Деньги 0.
- Риск: молчаливый пропуск блоков при ошибках — закрывается пунктом 5 и проверкой data-auditor на непрерывность номеров.
