## Возвращено в draft (Cowork, 2026-09-30)
Основание «фид регулярно закрывает соединение» — из потерянной сессии, не подтверждено: за ~20 мин записи в 001/002 сервер не закрыл соединение ни разу. Лимит «2 соединения на IP» тоже не проверен. При этом одно быстрое переподключение уже дало бан 403/3600. Вернуть в ready, если (а) 005 показал, что досылки по заголовку нет, и (б) несколько часов записи одним соединением покажут реальные закрытия сервером.

## Зачем
Фид регулярно закрывает соединение и не досылает пропущенное. Два соединения с разнесёнными переподключениями должны закрыть большую часть дыр без RPC и дать вторую метку времени прихода (полезно для оценки задержек позже).

## Контекст
- `references/chain-facts.md`: [источник] не больше 2 соединений с одного IP, третье получает 429.
- Задача 002: лестница пауз и `connections.tsv`.

## Что сделать
1. Два независимых соединения (A и B) в одном процессе, общий писатель. Для каждого `sequenceNumber` в сырьё пишется **первая пришедшая копия**; дубликат не пишется, но учитывается в статистике.
2. В строку сырья формат не меняется. Номер соединения и время прихода второй копии пишутся в отдельный файл `data/feed/dup-stats/…tsv` (seq, conn_first, recv_first_ns, recv_second_ns) — поминутно агрегированно, чтобы не раздувать диск.
3. Разнесённые переподключения: если одно соединение упало, второе не переподключается одновременно; минимум 30 с между попытками подключения двух соединений; общая лестница пауз на 429/403 — на IP, а не на соединение.
4. Дыра записывается в `gaps.tsv`, только если seq не пришёл ни по одному соединению.
5. Статистика раз в минуту в лог и в `data/feed/conn-stats.tsv`: доля seq, пришедших первыми по A и по B; медиана и p99 разницы времени прихода копий; закрытия по каждому соединению.
6. Флаг `--connections 1|2` (по умолчанию 2).

## Что НЕ делать
- Никогда не больше 2 соединений с одного IP.
- Не запускать тесты с IP будущего продакшен-сервера (решение 0003). Пока сервера нет — только Mac.

## Критерии приёмки
- Тесты: слияние двух потоков с перекрытием и дырами (синтетика) даёт правильный порядок, без дублей, дыры только где нет ни одной копии.
- 30 минут живой записи: дыр по `gaps.tsv` не больше, чем в режиме одного соединения за тот же период (сравнить с 001/002), статистика в отчёте.
- data-auditor: PASS — нет дублей seq в сырье, непрерывность номеров.

## Стоимость и риски
- Деньги 0. Риск 429/бана выше, чем при одном соединении → соблюдать п. 3; при первом 429 — остановить тест и описать.
