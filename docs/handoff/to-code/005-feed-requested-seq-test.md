# 005 — Тест: досылает ли публичный фид пропущенное по Arbitrum-Requested-Sequence-Number
status: done
phase: 1a
depends-on: 002
executor: indexer-engineer
reviewers: data-auditor

## Зачем
Если публичный фид поддерживает заголовок `Arbitrum-Requested-Sequence-Number` (в Nitro broadcast-клиенте он просит начать поток с заданного номера из бэклога), дыры после переподключения можно закрывать без RPC. Это меняет архитектуру дозаливки. Пока это гипотеза.

## Контекст
- Прежняя сессия наблюдала, что после переподключения пропущенное не досылается — но, по-видимому, без этого заголовка.
- Проверить по исходникам Nitro (`broadcastclient`), как именно клиент передаёт заголовок и что делает сервер (Context7 или репозиторий `OffchainLabs/nitro` на GitHub). Ссылку на файл и строку — в отчёт.

## Что сделать
1. Прочитать, как Nitro-клиент формирует заголовок и какие ещё заголовки передаёт (`Arbitrum-Feed-Client-Version` и т.п.).
2. Одно подключение с заголовком, запрашивая seq на 100, 1 000 и 10 000 блоков назад от текущего (три отдельных подключения с паузой ≥ 2 мин между ними).
3. Для каждого: первый полученный `sequenceNumber`, сколько блоков бэклога пришло, совпадают ли `blockHash` с RPC для 10 из них.
4. Результат записать в `references/chain-facts.md` как факт с датой — в любом случае (поддерживает / игнорирует / ограничено N блоками).

## Что НЕ делать
- Не больше 3 подключений за весь тест, с паузами. При первом 429/403 — остановиться.
- Не запускать с IP продакшен-сервера.
- Первое подключение — не раньше чем через 1 ч после любого другого подключения к фиду с этого Mac (бан 403/3600 из 002). Если до этого действует пауза в `connections.tsv` — ждать её конца.
- Не менять recorder, пока результат не разобран в Cowork.

## Критерии приёмки
- Однозначный ответ по трём глубинам с цифрами; факт добавлен в `chain-facts.md`.
- data-auditor подтверждает совпадение `blockHash` для полученного бэклога.

## Стоимость и риски
- 3 подключения, ~30 вызовов RPC. Деньги 0. Риск бана невелик при паузах.

## Формат отчёта
Сделано; ответ по каждой глубине; ссылка на код Nitro; что не получилось; предложение, как использовать в recorder (если работает).
