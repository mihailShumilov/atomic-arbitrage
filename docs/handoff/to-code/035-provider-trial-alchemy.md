## Что сделать
1. Чеки старых блоков: `eth_getBlockReceipts` на блоке 19400000 (3 отката, сверка с локальным файлом) и на 10 блоках ≥ 2 мес.; `eth_getBlockByNumber(full)`; совпадение с публичным RPC побайтно по `result`.
2. Пропускная способность: устойчивый rps на `eth_getBlockReceipts` (короткие ступени 5/10/20/40 rps, по ~20 вызовов, стоп на первом 429), время ответа p50/p95; сколько CU списано (по документации Alchemy: CU на метод) — оценка стоимости 20 млн / 50 млн блоков на PAYG и лимит 10 000 CU/s.
3. Пакеты: считается ли JSON-RPC batch как N вызовов (по CU и по rate limit), максимальный размер пакета.
4. Сжатие: `Accept-Encoding: gzip` — отдаёт ли сжатый ответ, коэффициент.
5. `eth_getLogs`: допустимый диапазон блоков и лимит ответа на Free; текст ошибки при превышении.
6. Метаданные пулов: v4 `Initialize` от PoolManager (`0x8366…0951`, observed) за период, покрывающий `data/` (через `eth_getLogs` окнами в пределах лимита), для v3-пулов из `data/` — `token0/token1/fee` (`eth_call`) у пулов фабрики `0x1f7d…2efa` (observed), `decimals()/symbol()` токенов. Результат — TSV реестра пулов/токенов в формате `crates/decoders/src/pools.rs` (статус `observed`, источник — этот прогон) в `data/registry/` (не в git) и прогон `swaps_scan` с ним: сколько строк `hood.swaps` теперь получается.
7. Бюджет: ≤ 3 000 вызовов, жёсткий счётчик в скрипте/`--max-calls`, свой User-Agent, стоп на повторных 429. Публичный RPC — 0 вызовов, кроме сверки п. 1 (≤ 20).
