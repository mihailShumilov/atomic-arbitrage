# Чек-лист: Bash (deploy/) и SQL (sql/)

## Bash
- `set -euo pipefail` (или осознанно без `-e` — с комментарием почему, как в healthcheck); `shellcheck -x` без замечаний.
- Общие функции (лог, notify, атомарная запись, проверка root, «изменилось ли») — в одном подключаемом файле или повторяются осознанно и коротко; разошедшиеся копии — замечание «важное».
- Идемпотентность: каждый шаг bootstrap проверяет состояние перед изменением и печатает CHANGED только при изменении; перезапуск служб — только при изменении их конфига.
- Кавычки вокруг всех переменных; массивы для списков аргументов; нет `eval`; временные файлы через `mktemp` + `trap`.
- Пути и пороги — переменные с умолчаниями в начале файла или в `/etc/hoodchain/*.env`, не магические числа в середине.
- Совместимость coreutils (GNU и uutils на 26.04): только флаги, проверенные в `deploy/test/`.
- Тестируемость: пути к `/proc/*`, `/srv/*`, бинарникам — переопределяются переменными окружения для тестов.

## Systemd
- Юнит: `User=`, `Restart=`, ограничения (`ProtectSystem`, `ReadWritePaths`, `NoNewPrivileges`) — минимально нужные; `systemd-analyze verify` чистый.

## SQL (ClickHouse)
- Миграции нумерованные (`NNN_*.sql`), только вперёд; изменение ключа сортировки — через новую таблицу и перенос.
- `ORDER BY` однозначно идентифицирует строку для `ReplacingMergeTree` (иначе тихое схлопывание разных строк); `PARTITION BY` — по месяцу/дню, не по высококардинальному полю.
- Типы: адреса `FixedString(20)`/`String` единообразно по всем таблицам; суммы в wei — `UInt256`/`Decimal`, не `Float64`; `LowCardinality` для перечислений.
- Сверка со скиллами `clickhouse-best-practices` и `hoodchain-mev/references/data-model.md` (при расхождении прав второй).
