# Чек-лист: Rust (crates/)

## Модули и границы
- Крейт = одна роль: `hood-core` — общие типы и чистые функции без IO; `recorder`/`enricher` — бинарники с IO; `decoders` — чистый разбор. Логика, нужная двум крейтам, живёт в `hood-core` (или в `decoders`), а не копируется.
- `main.rs` тонкий: разбор CLI, сборка зависимостей, запуск. Логика — в модулях `lib.rs`, чтобы её видели тесты.
- Модуль = одна ответственность (сеть, запись на диск, политика пауз, разбор). Смешение IO и решения («что делать») в одной функции — повод разделить: решение — чистая функция, IO — тонкая обёртка.
- Видимость минимальная: `pub(crate)` по умолчанию, `pub` — только реальный API.

## Типы и «ООП по-растовски»
- Доменные понятия — типы, а не голые `u64`/`String`: newtype для seq, номера блока, адреса, wei (`struct Seq(u64)`), enum вместо строковых флагов и `bool`-параметров.
- Состояние + поведение — `struct` с методами; полиморфизм — trait с узким интерфейсом (например, источник времени, транспорт, writer) — там, где нужна подмена в тестах или 2+ реализации. Trait «на вырост» с одной реализацией и без тестовой подмены — лишний.
- Композиция вместо глубоких иерархий; generic с trait bound для горячих путей, `dyn Trait` — для конфигурируемых точек.
- Невалидные состояния непредставимы: конструкторы проверяют инварианты (`TryFrom`, `new() -> Result`), поля приватны.
- Builder — когда параметров много и есть значения по умолчанию; не для 2–3 полей.

## Ошибки
- Библиотечный код — типизированные ошибки (`thiserror`-подобный enum, если зависимость уже есть, иначе свой enum); бинарники — `anyhow` с `.context("что делали")`.
- Никаких `unwrap`/`expect` на внешних данных (сеть, файлы, JSON фида, RPC). `expect` допустим для инвариантов с сообщением, почему они не нарушаются.
- Коды выхода и их смысл — в одном месте (константы), задокументированы.

## Асинхронность и IO
- Нет блокирующего IO внутри tokio-задач (fs/zstd — через `spawn_blocking` или отдельный поток, как writer).
- Отмена/остановка — через явный канал (`watch`/`CancellationToken`), а не флаги в глобальных переменных.
- fsync и атомарная запись (tmp + rename) — в одной утилите, не размазаны по коду.
- Таймауты и паузы — параметры/константы, не магические числа.

## Повторяющиеся места этого репо (проверять на дубли)
- разбор строки сырья `recv_ns\tseq_first\tseq_last\tJSON`, hex/адреса/unalias, чтение `*.jsonl.zst`, атомарная запись, повтор с `Retry-After`, лестницы пауз, разбор `gaps.tsv`/`filled.tsv`, topic0-константы.

## Тесты
- Чистые функции — юнит-тесты рядом (`#[cfg(test)] mod tests`); IO — интеграционные в `tests/` с моком на 127.0.0.1 и временным каталогом.
- Время — через параметр/trait, а не `SystemTime::now()` в глубине логики, иначе тесты зависят от часов.
- Фикстуры маленькие, с указанием источника (блок, дата).

## Стиль
- `cargo fmt`, clippy без предупреждений; комментарии и имена — по-английски; doc-комментарий у каждого `pub` элемента; нет закомментированного кода.
- Зависимости — только из `[workspace.dependencies]`, новая — с обоснованием.
