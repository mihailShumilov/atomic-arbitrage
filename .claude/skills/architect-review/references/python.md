# Чек-лист: Python (analytics/, .claude/skills/**/scripts/)

## Структура
- Скрипт > ~300 строк или с несколькими ролями (сбор, расчёт, вывод) — разбить на модули: `io` (чтение zstd/TSV/RPC), `metrics` (чистые расчёты), `report` (вывод). CLI — тонкий `main()` с `argparse`.
- Общий код для нескольких скриптов `analytics/` — в одном пакете/модуле (`analytics/common/…`), а не копиями: чтение `*.jsonl.zst`, RPC-клиент с бюджетом и User-Agent, разбор строки фида, unalias, константы topic0.
- Никакой логики на уровне модуля (кроме констант) — всё под `if __name__ == "__main__":`.

## Типы и классы
- Записи данных — `@dataclass(frozen=True, slots=True)` или `NamedTuple`, а не словари с ключами-строками по всему коду.
- Класс — когда есть состояние + поведение (RPC-клиент с бюджетом и rate limit, накопитель метрик). Набор функций без состояния — модуль, не класс.
- Аннотации типов у публичных функций; `from __future__ import annotations`.
- Enum вместо строковых флагов.

## Надёжность
- Внешние вызовы (RPC) — один клиент с жёстким бюджетом, паузой, своим User-Agent, обработкой 429/403 — переиспользуется, а не пишется заново в каждом скрипте.
- Исключения — конкретные типы, не голый `except:`; сообщения с контекстом.
- Время — timezone-aware (`datetime.now(UTC)`, `fromtimestamp(ts, UTC)`), не `utcnow`/`utcfromtimestamp`.
- Числа в wei — `int`, не `float`; деление для отображения — в последнюю очередь.
- Детерминизм: seed у случайных выборок записан в отчёте.

## Линт
- `uvx ruff check --select E,F,W,B,UP,SIM,PL,RUF`, `uvx ruff format --check`; stdlib-only, если скрипт должен работать на сервере без pip.
