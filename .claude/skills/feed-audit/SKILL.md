# feed-audit — проверка записи фида

Один скрипт на все проверки записи, чтобы цифры в отчётах считались одинаково. Факты о фиде — в скилле `hoodchain-mev` (`references/chain-facts.md`); при расхождении прав он.

Скрипт независим от `analytics/` (в том числе от `analytics/hoodlib.py`) и ставится на сервер одним файлом (`deploy/bootstrap.sh` → `/opt/hoodchain-mev/deploy/feed_audit.py`). Источник истины о формате фида — recorder (Rust) и `references/data-model.md`; `feed_audit.py` — независимая проверка, поэтому разбор фида и RPC-сверка в нём написаны заново, а не взяты из общего кода.

## Запуск

```bash
# одна запись или сутки; glob можно передать строкой
python3 .claude/skills/feed-audit/scripts/feed_audit.py \
  --feed-root data/feed --rpc-sample 20 'data/feed/2026/09/30/feed-*.tsv.zst'
# --json — машиночитаемая сводка для отчёта
# без сети: --rpc-sample 0 (RPC не вызывается вообще)
```

Нужны Python 3.9+ (только stdlib; на Mac 3.9, на сервере 3.14) и `zstd` CLI. `RPC_URL` берётся из окружения, иначе публичный RPC. `--rpc-sample N` делает один пакетный запрос на N блоков. Вызовов немного, но на публичном RPC не ставь больше ~50. Скрипт ничего не пишет на диск.

Прочие флаги:
- `--session-gap-s 30` — пауза между соседними строками, после которой начинается новая сессия (см. ниже);
- `--current-hour YYYYMMDD-HH` — какой час считать открытым (по умолчанию час из `--now`). Нужен для проверки старых записей и тестов;
- `--now YYYY-MM-DDTHH:MM:SSZ` — время аудита (по умолчанию текущее UTC). От него считается окно для фрейма прошлого часа, см. ниже;
- `--frame-secs 60` — `--frame-secs` recorder'а. Задаёт, сколько после начала часа фрейм прошлого часа может оставаться открытым;
- `--seed N` — seed выборки для `--rpc-sample` (с задачи 028). По умолчанию берётся `time_ns()`. При `--rpc-sample > 0` seed всегда печатается в `rpc.seed`, и прогон с тем же `--seed` на тех же файлах сверяет те же блоки. Без выборки seed печатается, только если задан явно (`rpc {'seed': N}`). Без `--seed` и при `--rpc-sample 0` вывод прежний: `rpc {}`.

Код выхода: 0 — PASS, 1 — FAIL (в том числе «no blocks found»), 2 — ошибка запуска (нет файлов, плохой `--now`). Необработанное исключение Python тоже даёт 1, но без строки `verdict`; ежедневная обёртка `deploy/feed-audit-daily.sh` решает по коду выхода, а строку `verdict` использует только чтобы отличить FAIL от падения.

Игнорируются, даже если попали в glob: всё внутри `_torn/`, `connections.tsv`, `*.tmp`, любые имена не вида `feed-*.tsv.zst` (счётчик `ignored_inputs`).

## Что проверяет

| Проверка | Итог при нарушении |
|---|---|
| Целостность по zstd-фреймам: каждый целый фрейм распаковывается и сходится с контрольной суммой | FAIL |
| Байты после последнего целого фрейма: один недописанный фрейм в файле **текущего** часа — это открытый фрейм, recorder ещё пишет (`open_tail`, не проверяется) | не FAIL |
| Недописанный фрейм в файле **прошлого** часа, если аудит запущен раньше `HH:00 + frame-secs + 60 с` и в файле текущего часа ещё нет ни одного целого фрейма: recorder мог ещё не закрыть фрейм (с задачи 009). Попадает в `open_tail` с пометкой `previous hour … frame may still be open` | не FAIL |
| То же в **закрытом** часе (оборванный хвост) или мусор вместо фрейма | FAIL |
| 4 TSV-столбца, целые `recv_unix_ns`/`seq_first`/`seq_last`, валидный JSON, seq_first/seq_last = JSON | FAIL |
| у каждого сообщения конверта целые `sequenceNumber`, `message.message.header.kind` и `header.blockNumber`; конверт другой формы (или не объект JSON) считается в `bad_envelopes` и пропускается, аудит идёт дальше (с задачи 024; раньше скрипт падал с `KeyError`) | FAIL |
| sequenceNumber строго +1, без дублей и откатов | FAIL |
| каждая дыра покрыта строками `gaps.tsv` (нужен `--feed-root`). С задачи 009 смежные и перекрывающиеся строки перед сверкой склеиваются: дыра, записанная двумя строками подряд, считается покрытой | FAIL |
| `recv_unix_ns` не убывает (по всем строкам, включая seq 0) | FAIL |
| строка с seq 0, в которой есть `messages` | FAIL |
| строки с seq 0 «прочие» (не `recorderFrame` и не `confirmedSequenceNumberMessage`, либо битый base64) | WARN |
| blockHash = RPC на выборке (всегда первый, последний и часть отложенных сообщений kind ≠ 3) | FAIL |
| l1BlockNumber из RPC = `header.blockNumber` для kind 3 и нарастающему максимуму для kind 9/13 | WARN (модель проверена 2026-09-30) |
| `last_seq.txt` ≠ последнему seq (нормально, если передан не последний файл или есть открытый фрейм) | WARN |

Цифры:
- `lines` — все строки; `envelopes` — только строки с блоками (seq ≠ 0); `bad_envelopes` — строки с seq ≠ 0 и валидным JSON, но неверной формой конверта (в `envelopes` не входят, их seq становятся дырой);
- `seq0_lines` — строки с seq 0 по типам: `recorderFrame:<opcode>` (ping, pong, close, binary, text — текст, который не JSON), `confirmedSequenceNumberMessage`, `other`, `with_messages`;
- блоков, ожидалось, пропущено, виды `header.kind`, число zstd-фреймов;
- сессии (`session_list`), `session_s`, **блоков/с и МБ/ч по времени сессий**;
- `recv_span_s`, `blocks_per_s_span`, `mb_per_hour_span` — по всему интервалу от первой до последней строки, вместе с простоями;
- интервал между конвертами (p50, p99, max) — только между соседними строками с блоками внутри одной сессии.

## Как читать результат

- **Дыра в `gaps.tsv`** — ожидаемое поведение после переподключения. Её закрывают дозаливкой через enricher, и это отдельная проверка. Дыра **не** в `gaps.tsv` — ошибка recorder. С задачи 008 recorder при старте сам дописывает в `gaps.tsv` разрывы в двух последних файлах, которых там нет (событие `gap_reconciled` в `connections.tsv`).
- **Граница часа.** Фрейм прошлого часа recorder закрывает при первой строке нового часа, а если строк нет — по сроку фрейма (до `frame-secs`). Поэтому аудит, запущенный в первые `frame-secs + 60` с часа, пока в файле нового часа нет целого фрейма, не даёт FAIL на хвост прошлого часа, а помечает его в `open_tail`. Позже, или если в новом часе фрейм уже есть, такой хвост — FAIL. Для cron надёжнее запускать аудит через несколько минут после начала часа.
- **Файл текущего часа** во время записи: recorder закрывает zstd-фрейм не реже раза в 60 с, поэтому в открытом часе недописан не больше одного фрейма (последней минуты). Скрипт его пропускает и показывает в `open_tail`, это не FAIL. Оборванный хвост в закрытом часе — FAIL: recorder упал и ещё не перезапускался (при старте он переносит хвост в `_torn/`). Старые файлы задачи 001 (один фрейм на час) в открытом часе целиком попадают в `open_tail`.
- **Сессии.** Запись режется на сессии по событиям `connected` из `<feed-root>/connections.tsv` (если файл есть) и везде, где между соседними строками больше `--session-gap-s` (30 с). Сессия длится от первой до последней своей строки. Поэтому простой и бан не занижают блоков/с и МБ/ч. Во время соединения строки идут чаще раза в 2 с (ping), так что порог 30 с внутри сессии не срабатывает.
- **Блоков/с и МБ/ч** считаются по `recv_unix_ns`, то есть по времени прихода, а не по меткам блоков. Метки блоков имеют разрешение в 1 с и немонотонны у отложенных сообщений.
- Скрипт проверяет запись, а не декодирование. Проверку декодеров и `hood.*` по-прежнему делает data-auditor по своему списку.

## Тесты

```bash
python3 -m unittest discover -s .claude/skills/feed-audit/scripts -v
```

`test_feed_audit.py` (stdlib `unittest`, на сервер не ставится): чистые функции (`frame_len`, `split_frames`, `merge_ranges`, `classify_seq0`, разбор конверта, время) и сквозные прогоны на синтетических `.tsv.zst` во временном каталоге — нормальный день, битый конверт, дыра вне и внутри `gaps.tsv`, дубль, открытый хвост текущего и прошлого часа, мусор после фреймов, строки seq 0, сессии, `last_seq.txt`, ошибки запуска, JSON глубокой вложенности (`RecursionError` → `bad_json`, а не «zstd failed»), исключение посреди большого файла (процесс завершается, а не висит на канале zstd). `DeprecationWarning` в тестах — ошибка. Нужен `zstd` CLI, без него сквозные тесты и случаи с настоящим zstd-фреймом пропускаются; разбор заголовков фреймов, которому фрейм из zstd не нужен (skippable, мусор, обрезанный magic), и детерминизм выборки RPC по seed проверяются и без zstd (с задачи 028). Сквозной тест `--seed` подменяет `rpc_blocks`, сети нет.
