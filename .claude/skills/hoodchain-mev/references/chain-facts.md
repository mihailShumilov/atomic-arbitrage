# Факты о Robinhood Chain

Каждый факт помечен: **[проверено]** — на живых данных, с датой и способом; **[источник]** — из внешнего источника, не перепроверялось руками. Новые факты добавляй в тот же формат.

## Сеть

- **[проверено 2026-09-28]** Chain ID `4663` (`eth_chainId` → `0x1237`).
- **[проверено 2026-09-28]** Публичный RPC: `https://rpc.mainnet.chain.robinhood.com`. Ограничен по частоте, не для продакшена — для загрузки истории нужен провайдер.
- **[проверено 2026-09-28]** Base fee наблюдался `0x1312d00` = 0.02 gwei. Комиссии сильно менялись (в начале сентября рост ~25×, затем падение ~97%) — не хардкодить.
- **[источник: glassnode, docs]** Arbitrum Orbit, упорядочивание FCFS строго по времени прихода к секвенсору; priority fee не даёт обгона; Timeboost / express lane нет.
- **[проверено 2026-09-28]** ~10.2 блока в секунду (246 блоков за 24.2 с записи фида), т.е. ~100 мс на блок.
- **[источник: glassnode]** Секвенсор в AWS us-east-2 (Огайо).
- **[источник]** Субсидия газа для Robinhood Wallet заканчивается ~29.09.2026 — граница режима для любых сравнений «до/после».
- **[источник: L2BEAT]** У секвенсора есть фильтр транзакций (compliance filter); отфильтрованные транзакции могут быть аннулированы.

## Фид секвенсора

- **[проверено 2026-09-28]** URL: `wss://feed.mainnet.chain.robinhood.com`. За Cloudflare (`server: cloudflare`, `x-backend-service: arb-relay`, cookie `__cflb` — балансировщик).
- **[проверено 2026-09-28]** Требуется permessage-deflate; сервер согласует `server_no_context_takeover; client_no_context_takeover`. `tungstenite 0.30` deflate не умеет — используем `yawc`.
- **[проверено 2026-09-28]** Апгрейд WebSocket поверх HTTP/2 вернул 520; используем ALPN `http/1.1`.
- **[источник]** Не больше 2 соединений с одного IP (третье получает 429).
- **[проверено 2026-09-28]** Формат конверта:
  ```
  {"version":1,"messages":[{"sequenceNumber":N,
    "message":{"message":{"header":{"kind":3,"sender":"0xa4b0…7265…","blockNumber":<L1>,"timestamp":<сек>,"requestId":null,"baseFeeL1":0},
               "l2Msg":"<base64>"},"delayedMessagesRead":…},
    "blockHash":"0x…","signatureV2":"<base64>","blockMetadata":null}]}
  ```
- **[проверено 2026-09-28]** `sequenceNumber` == номер L2-блока: `blockHash` из фида совпал с `eth_getBlockByNumber` для блоков 74755960 и 74755961.
- **[проверено 2026-09-28]** `header.blockNumber` — номер **L1**-блока (совпал с `l1BlockNumber` в L2-блоке).
- **[проверено 2026-09-28]** `header.timestamp` в секундах; несколько L2-блоков имеют одну метку.
- **[проверено 2026-09-30, задача 001: 20 блоков через enricher + 5 через RPC]** Уточнение к предыдущему пункту: `header.blockNumber` равен `l1BlockNumber` из RPC **только для kind 3** (сообщения секвенсора). У отложенных сообщений из L1-inbox (kind 13 и 9) там L1-блок, в котором сообщение попало в inbox. Он на 30–90 L1-блоков старше, а `header.timestamp` на сотни секунд старше. Пример: блок 76491181 (kind 13) — в фиде 26090029 / 1790768099, в RPC l1BlockNumber 26090092. `l1BlockNumber` в RPC совпал с нарастающим максимумом `header.blockNumber` по фиду во всех 25 проверенных точках. Поэтому `header.blockNumber` и `header.timestamp` из фида немонотонны, и их нельзя брать как L1-блок или время L2-блока. Эти значения нужно брать из RPC.
- **[проверено 2026-09-30, задача 001: 10 мин, 6015 блоков]** Виды `header.kind` за 10 минут: 3 — 5990, 13 — 24, 9 — 1. Каждое отложенное сообщение приходит отдельным L2-блоком (в проверенных блоках по 2 транзакции). `delayedMessagesRead` вырос ровно на 25. Расшифровка kind 9 = SubmitRetryable, 13 = BatchPostingReport взята из нумерации ArbOS и на данных не проверялась.
- **[проверено 2026-09-30, задача 001]** 10 минут записи с Mac, одно соединение: 6015 блоков подряд без дыр, 9.97 блока/с. Интервал между конвертами: p50 114 мс, p99 171 мс, max 977 мс. В каждом конверте ровно 1 сообщение. Сервер за 10 минут ни разу не закрыл соединение.
- **[проверено 2026-09-28]** Объём сырого фида: ~0.57 МБ за 24 с при zstd-3 → порядка 85 МБ/ч, ~2 ГБ/сутки, ~60 ГБ/мес. Уточнить на сутках записи.
- **[проверено 2026-09-30, задача 001]** Уточнение объёма: 15.18 МБ сжатого файла за 603 с (111.2 МБ в распакованном виде, zstd-3 сжал в ~7.3 раза) → 90.6 МБ/ч, то есть ~2.2 ГБ/сутки и ~65 ГБ/мес.
- **[источник: chainstacklabs]** Блок уже исполнен к моменту рассылки: фид опережает ноды, которым нужно переисполнить блок, но не само исполнение. В фиде нет чеков, логов и статуса revert.

## RPC

- **[проверено 2026-09-30]** Публичный RPC (за Cloudflare) отвечает 403 на запрос с User-Agent по умолчанию `Python-urllib/3.x`. curl и reqwest (enricher) проходят. В скриптах задавай свой User-Agent.
- **[проверено 2026-09-28]** `eth_getBlockReceipts` поддерживается; в чеке есть `status`, `gasUsed`, `gasUsedForL1`, `effectiveGasPrice`, `from`, `to`, `logs`. Значения `value` и `input` — только в `eth_getBlockByNumber(full=true)`.
- **[не проверено]** Поддержка `debug_traceBlock*` (нужна для внутренних переводов ETH в графе финансирования) — проверить у выбранного провайдера.

## Launchpad'ы (по внешним источникам, перепроверить по официальной документации)

- **[источник: Bitquery]** Pons: комиссия 1% с каждой покупки и продажи плюс ранний сбор, убывающий с возрастом монеты; около 2 из 3 кошельков, торговавших монетами Pons, в минусе; «выпускается» меньше 1 из 60 монет.
- **[источник: разные]** Pons v1: токен + пул Uniswap v3 с первого блока, без кривой; «выпуск» при 4.2 ETH — это флаг, а не миграция; в блоке запуска исполняется только покупка создателя, затем лимит 5% предложения на кошелёк в течение окна защиты.
- **[источник]** Pons v2 (с 04.08.2026): бондинг-кривая, выпуск в заблокированный пул Uniswap v4; параметры комиссий могут отличаться у каждого запуска и читаются в цепи.
- **[источник]** pools.trade (Uniswap Labs, с 05.08.2026): без кривой, пул Uniswap v4 с первого блока.
